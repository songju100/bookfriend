# 문학 추천과 학교 소장도서 검색 요구사항

## 목적

문학 주제를 선택해도 우리 학교 도서관의 문학 도서 후보를 찾을 수 있게 하고, 학생이 학교 소장도서를 PC·태블릿·휴대전화에서 검색해 청구기호를 확인하도록 한다.

## 상세 기능 정의

- 제공된 `dls소장도서.xlsx`의 `리스트 반출` 시트를 기준으로 한다. 워크북에는 총 13,623건이 있으며, 그중 `단행본`은 13,193건, `비도서자료`는 430건이다.
- `단행본`만 웹 검색용 목록으로 변환한다. 보존 필드는 자료명, 저자, 출판사, 출판년도, 청구기호다. 등록번호, 대출·자료 상태, 반납예정일, 입수구분, 화폐구분, 가격은 공개 데이터에 포함하지 않는다.
- 엑셀에 ISBN과 책 소개글이 없으므로 자동으로 만들어내지 않는다. 소장도서 검색 결과는 서지정보와 청구기호를 보여 주고, 교보문고 제목 검색 링크를 제공한다.
- 청구기호 분류가 문학(800번대)인 단행본을 `문학` 주제 결과에 포함한다. 기존 추천 데이터에 `문학` 책이 있으면 함께 표시하고, 같은 제목·저자는 중복 표시하지 않는다.
- 별도 `우리학교 소장도서 검색` UI에서 제목·저자·출판사 키워드를 검색한다. 모바일·태블릿에서 사용할 수 있도록 목록은 검색 후 필요한 범위만 표시한다.
- 현재 정적 GitHub Pages 방식에서는 브라우저가 PC의 E: 드라이브 파일을 직접 읽을 수 없다. 제공된 엑셀에서 위 필드만 추린 검색용 JSON을 생성해 사이트에 포함한다. 목록 갱신 시 교사가 새 엑셀로 검색용 JSON을 다시 생성해 저장소에 반영한다.

## UI 변경점

- `문학` 주제 선택 시 학교 소장 문학도서가 추천 후보로 나타나며 각 결과에 청구기호와 교보문고 검색 링크를 표시한다.
- 도서 추천 화면에 학교 소장도서 검색 칸과 결과 목록을 추가한다.
- 결과가 많을 때는 제목·저자 검색으로 좁힐 수 있게 한다.

## 예외 처리

- 800번대 청구기호가 없거나 형식이 달라 자동 분류할 수 없는 도서는 임의로 문학으로 지정하지 않는다.
- 제목이나 저자 정보가 비어 있는 행은 제외한다. 같은 도서는 제목·저자 기준으로 중복을 제거한다.
- 소장 목록은 엑셀 내보내기 시점의 자료다. 실시간 대출 가능 여부를 표시하지 않으며 실제 서가에서 확인하도록 안내한다.
- 검색용 JSON은 공개 GitHub 저장소와 Pages에서 누구나 내려받을 수 있다. 따라서 위에 지정한 서지 필드 외의 내부 식별자·상태·가격 정보는 절대 포함하지 않는다.
- 엑셀 원본에는 소개글이 없으므로 소장 검색 결과에 소개글이 자동 제공된다고 표시하지 않는다. 책 소개는 교보문고 링크에서 확인한다.

## 완료 검증 기준

- `문학`을 선택했을 때 800번대 청구기호가 확인된 학교 소장 단행본이 표시된다.
- 학교 소장도서 검색에서 제목·저자·출판사 키워드로 결과를 찾고 청구기호를 확인할 수 있다.
- 결과의 교보문고 링크가 검색 대상 도서 제목을 사용한다.
- 공개 데이터에 등록번호, 대출·자료 상태, 반납예정일, 입수구분, 화폐구분, 가격 필드가 없다.
- 검색 목록은 사용자가 새로고침해도 페이지 초기 표시와 태블릿 사용성을 과도하게 저하시키지 않도록 필요할 때 불러온다.

## 수정 대상

- `data/holdings.json`: 엑셀에서 추린 공개용 단행본 검색 목록.
- `index.html`: 문학 주제 연동, 소장도서 검색 UI·필터·결과 표시.
- `.github/workflows/pages.yml`: 검색용 JSON 배포 포함 여부 확인 및 반영.
